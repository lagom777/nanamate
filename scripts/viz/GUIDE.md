# 영단어장 '그림만 해설' SVG 제작 가이드

영어 단어 하나의 **뜻을 글자 없이 움직이는 그림만으로** 설명하는 SVG 파일을 만든다. 학습자는 그림을 보고 단어와 뜻을 떠올려야 하므로,
**그림만 보고도 뜻이 전달되는 것**이 최우선이다. 예쁘기만 하고 뜻이 안 전달되면 실패다.

## 산출물

- 파일 하나 = 단어 하나: `out/<소문자단어>.svg` (예: `out/cottage.svg`). 하이픈·공백이 있으면 제외한 소문자.
- 그릴 수 없는 단어는 **파일을 만들지 말고** `out/SKIPPED.txt`에 `단어: 이유` 한 줄로 적는다. 억지로 엉뚱한 그림을 만드는 것보다 낫다.
- 다 만든 뒤 `node validate-viz.mjs out` 를 돌려 전부 통과할 때까지 고친다(통과 못 한 파일은 쓰지 않은 것으로 간주).

## 파일 형식

```svg
<svg xmlns="http://www.w3.org/2000/svg" data-n="3" data-t="4.2" data-c="#2b8cc4" viewBox="0 0 560 300" role="img" aria-label="한국어 한 줄 설명">
  ...
</svg>
```

- `viewBox`는 반드시 `0 0 560 300`. `data-n` = 단계 수(2~5). `data-t` = 한 단계 길이(초, **1.5~4.0**, 단어의 동작 속도에 맞게: 빠른 충돌·튕김 1.5~2.0, 보통 2.0~2.8, 천천히 변하는 과정(썩음·침식·성장) 3~4). 장면 안 등장·이동 시간(`--d`,`--dl`)은 페이지가 `data-t/4` 배율로 자동으로 줄이므로 `--d`는 4초 단계 기준(예: 1.4s)으로 적으면 된다. `data-c` = 대표색 #rrggbb.
- `aria-label`만 한국어 설명이다. **화면에 보이는 글자(`<text>`)는 절대 금지.** 숫자·알파벳·한글 모두 금지. 화살표는 `<path>` 도형으로 그린다(마커 쓰지 말고 삼각형 `<path>`로).
- 모든 `id`는 `<단어>_`로 시작한다(예: `cottage_clip`, `cottage_sky`). 한 페이지에 한 번에 한 장면만 들어가지만 다른 장면 id와 겹치면 안 된다.
- 전체를 둥근 모서리로 자른다:
  ```svg
  <defs><clipPath id="cottage_clip"><rect width="560" height="300" rx="14"/></clipPath></defs>
  <g clip-path="url(#cottage_clip)"> ... 모든 내용 ... </g>
  ```
- `<style>`, `<script>`, `<animate*>`, `<set>`, `<use>`, `<image>`, `<foreignObject>`, 외부 링크, `on*` 속성 금지. 애니메이션은 아래 **클래스만** 쓴다(CSS는 페이지가 이미 가지고 있다).
- 파일 용량은 10KB 안팎(최대 16KB). 경로는 단순하게.

## 단계(step) 모델

장면은 1…n단계를 차례로 재생한다. 각 단계는 `data-t`초 동안 지속된다. 1단계가 시작되면 `data-s="1"`인 요소가 나타나고, 다음 단계가 되면 `data-s="2"`인 요소가 나타난다…
**마지막 단계가 끝나면 최종 장면이 그대로 남는다**(그 상태가 완성도 높은 한 장의 그림이어야 한다). 다시 재생하면 0단계(요소가 아직 안 나타난 상태)부터 시작한다.

- `data-s="k"`: k단계부터 보인다(또는 움직인다). `data-e="m"`: m단계까지만 보인다(생략하면 끝까지).
- 단계마다 눈에 띄는 **새로운 변화**가 있어야 한다. 1단계는 '시작 상황'(필요하면 처음부터 보이는 정지 요소 + `data-s="1"` 요소), 마지막 단계는 '결과/핵심'.
- 원인 → 결과, 전 → 후, 시작 → 도착처럼 **시간 순서**가 읽히게 한다. 뜻이 여러 개인 단어는 뜻마다 한 단계씩.

## 클래스 사전

### 나타나기 (`.vs` 필요 — data-s 필수)
`.vs` = `data-s` 단계 전까지 투명(opacity 0). 아래를 **함께** 달아 등장 방식을 고른다.

| 클래스 | 효과 | 비고 |
|---|---|---|
| `vs` | 서서히 나타남 | 기본 |
| `vs up` | 12px 아래에서 올라오며 나타남 | |
| `vs pop` | 커지며 나타남(중심 기준) | 작은 알갱이·아이콘·폭발 |
| `vs wipe` | 왼→오른쪽으로 닦이듯 나타남 | 화살표·선·물이 차오르는 느낌(가로) |
| `vs wipe-d` | 위→아래로 나타남 | |
| `vs draw` | 선이 그려짐 | 반드시 `pathLength="1"` + 선(stroke)만, `fill="none"` |

타이밍 변수(`style` 속성): `--dl:.6s`(시작 지연), `--d:1.6s`(wipe/draw 길이). 지연+길이는 `data-t`보다 0.5초 이상 짧아야 한다.

### 움직이기 (`.mv` — data-s 필수, `.vs` 아님)
`.mv`는 **항상 보이는** 요소이고, `data-s` 단계가 되면 `style="--from:…"`의 변환에서 **원래 자리로** 이동한다.
**요소의 기본 좌표 = 최종 위치**로 그리고, `--from`에 출발 변환을 쓴다.
```svg
<g class="mv" data-s="2" style="--from:translateX(-120px);--d:1.4s;--dl:.2s;--ease:cubic-bezier(.4,0,.2,1)">…</g>
```
- 확대/회전은 중심을 인라인으로 지정: `style="--from:scale(.5);transform-box:fill-box;transform-origin:50% 100%"`.
- `.mv`에 `data-e`를 쓰면 그 단계를 지날 때 **출발 자리로 되돌아가는 움직임**이 보인다. 사라져야 하는 물체는 바깥을 `.vs`(data-s/data-e)로, 안쪽을 `.mv`(data-e 없음)로 겹쳐라.
- 한 물체를 단계마다 다른 위치로 보내려면 `.mv`를 겹쳐 쓰고 합이 맞게 설계한다(reference/collide.svg).

### 계속 도는 움직임 (`a-*`, data-s 불필요)
요소가 보이는 동안 계속 반복된다. 보이게 하려면 바깥을 `.vs`로 감싸라.
`a-fall` 눈·비·알갱이가 떨어짐(3.2s, 아래로 40px) · `a-drip` 물방울 한 방울 떨어짐 · `a-rise` 김·연기·열이 올라감 · `a-dash` 점선이 흐름(요소에 `stroke-dasharray="10 9"` 필요, 경로 방향으로 흐름) · `a-bob` 위아래로 살랑(±3px) · `a-flap` 날갯짓(`transform-origin` 아래) · `a-pulse` 파문처럼 퍼졌다 사라짐 · `a-slide` 파도·물결이 좌우로 미끄러짐(경로를 화면보다 길게) · `a-flow` 입자·혈구가 한 방향으로 흐름 · `a-flip` 뒤집히듯 회전(모래시계) · `a-press` 아래로 꾹 누름.

### 반드시 지킬 규칙(자주 틀리는 것)
1. **CSS `transform`이 SVG `transform` 속성을 덮어쓴다.** `up/pop/mv/a-*` 클래스를 단 요소에는 `transform="…"` 속성을 달지 말고, 위치 이동은 **바깥 `<g transform="translate(x y)">`** 로 분리한다. (예: `<g transform="translate(440 88)"><g class="vs pop" data-s="2">…</g></g>`)
2. `wipe`/`wipe-d` 요소에 `clip-path` 속성을 같이 달지 않는다(바깥 `<g clip-path>`로).
3. 한 요소에 변환을 만드는 클래스(`up pop mv a-*`)는 하나만. 겹치면 바깥/안쪽 `<g>`로 나눈다.
4. `data-s` 범위는 1~`data-n`. `.vs`·`.mv`에는 반드시 `data-s`.
5. 선 그리기(`draw`)는 `fill="none"`인 `<path>`에만. `pathLength="1"`.
6. 화살표 머리는 별도 삼각형 `<path d="M x y L x y L x y Z"/>`로. (`wipe`는 clip을 쓰므로 마커가 잘린다.)

## 그림 설계 원칙

- **주인공이 분명한 한 장면**: 화면 중앙 60% 안에서 물체가 크고 읽히게. 잡다한 배경 금지. 바닥선·하늘·단순한 그라데이션 정도.
- 평평하고 깔끔한 일러스트 스타일(둥근 도형, 부드러운 그라데이션, 바닥 그림자 타원). 팔레트는 `data-c` 계열 + 중립색. 대비가 선명해야 한다(작은 폰 화면에서도 읽혀야 함).
- 뜻을 **행동·변화**로 보여 줘라. 형용사는 '그 성질이 드러나는 상황'(예: 무거움 = 저울이 기울고 바닥이 꺼짐), 추상어는 **일상의 구체적 장면**으로.
- 글자 대신 쓸 수 있는 보편 기호: 화살표, 느낌표 모양(`path`), 체크/엑스 모양, 반짝임, 물방울, 번개, 하트, 눈 모양, 돋보기, 저울, 시계/모래시계, 온도계, 전구, 폭발(별 모양) 등.
- 다의어는 중심 이미지에서 갈라지는 뜻 2~3개를 단계마다 보여 준다(reference/ 의 vessel 방식).
- 단어 철자나 어원을 힌트로 그릴 필요 없음. **뜻**만.
- 각 단계의 새 요소가 이전 단계와 겹쳐 가리지 않게 위치를 잡는다.

## 점검표 (쓰기 전에)

- [ ] 글자(`<text>`) 없음, `aria-label`만 한국어
- [ ] viewBox `0 0 560 300`, `data-n` / `data-t`(3~6) / `data-c`
- [ ] 모든 id가 `<단어>_`로 시작, `url(#…)` 대상 존재
- [ ] 각 단계(2~n)에 `data-s` 요소가 있음, 마지막 장면이 완성된 그림
- [ ] 변환 클래스 요소에 transform 속성 없음
- [ ] `node validate-viz.mjs out` 전부 통과
