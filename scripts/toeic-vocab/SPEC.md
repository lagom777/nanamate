# 토익 단어장 '움직이는 해설' 제작 명세

토익 빈출 단어 하나마다 **파일 두 개**를 만든다. 둘 다 `public/learn/aboutToeicVocab/viz/` 에 둔다.

| 파일 | 내용 | 규칙 |
|---|---|---|
| `<단어>.svg` | 단계별로 움직이는 그림(글자 없음) | **`scripts/viz/GUIDE.md` 를 그대로 따른다** (수능 단어장과 같은 재생기·같은 클래스) |
| `<단어>.json` | 카드 정보 + 단계별 한국어 해설 | 아래 형식 |

페이지(aboutToeicVocab)는 SVG 장면 위에 단어·뜻·`lead` 를, 아래에 `steps` 를 번호 목록으로 보여 준다.
재생하면 1단계 그림이 나오면서 `steps[0]` 이 강조되고, 다음 단계로 넘어가면 `steps[1]` … 이렇게 **그림 단계와 설명이 한 줄씩 짝지어** 움직인다.
그러니 **`steps` 개수 = SVG `data-n`**, 그리고 k번째 설명은 k단계에서 새로 나타나는 그림을 설명해야 한다.

## JSON 형식

```json
{
  "w": "overtime",
  "e": "over(넘어서) + time(시간) → 정해진 시간을 넘긴 → 초과 근무",
  "note": "work overtime 초과 근무하다 · overtime pay 초과 근무 수당",
  "icon": "⏰",
  "ipa": "/ˈoʊvərtaɪm/",
  "tag": "움직이는 해설 · 인사·채용",
  "lead": "정해진 근무 시간이 끝난 뒤에도 계속 일하는 것 — 토익에서는 수당(pay)·승인(approve)과 함께 자주 나온다",
  "steps": [
    ["정규 근무 시간", "시계가 6시를 향해 가는 동안 직원이 책상에서 일합니다", "regular working hours — 정규 근무 시간"],
    ["시간을 넘겨서도", "퇴근 시각이 지나 창밖이 어두워졌는데도 일이 계속됩니다", "work overtime — 초과 근무하다"],
    ["그만큼 더 받는 돈", "넘긴 시간만큼 동전이 쌓입니다 — 초과 근무 수당", "overtime pay — 초과 근무 수당"]
  ],
  "ex": ["All overtime must be approved by your supervisor in advance.", "모든 초과 근무는 사전에 상사의 승인을 받아야 합니다."],
  "rel": [["shift", "교대 근무"], ["payroll", "급여 대장"], ["paid leave", "유급 휴가"]]
}
```

| 키 | 설명 |
|---|---|
| `w` | 소문자 표제어 (파일 이름과 같게) |
| `e` | **어원** 한 줄. 수능 단어장과 같은 형식: `어근(뜻) + 어근(뜻) → 풀이 → 뜻`. 반드시 ` → ` 를 쓴다. 라틴어·프랑스어 등은 `라틴어 merx(상품) → …` 처럼 언어 이름을 앞에 붙여도 된다. 어근은 `영문(한국어 뜻)` 꼴로 (카드가 이걸 블록 그림으로 바꾼다). 확실하지 않은 어원은 지어내지 말고 아는 범위까지만. |
| `note` | **토익 빈출 표현** 1~3개, ` · ` 로 구분. `영어 표현 한국어 뜻`. Part 5 함정(품사·전치사 짝)도 좋다: `be eligible for ~할 자격이 있다 · eligible to do`. |
| `icon` | 단어를 나타내는 이모지 1개 |
| `ipa` | 미국식 발음 기호 `/…/` |
| `tag` | `움직이는 해설 · <주제 이름>` (주제 이름은 배치 파일에 있음) |
| `lead` | 핵심을 한두 문장으로. 비슷한 단어와의 차이, 토익에서 쓰이는 장면을 담으면 좋다. |
| `steps` | `[제목, 설명, 예시 표현(선택)]` × `data-n`. 제목은 짧게(15자 안팎), 설명은 **그 단계 그림에서 보이는 것** + 뜻을 한 문장. 세 번째 칸은 `영어 표현 — 한국어` 꼴의 짧은 연어(collocation). 다의어(예: promotion 승진/판촉, balance 잔액/균형)는 뜻마다 한 단계. |
| `ex` | `[토익 스타일 영어 예문, 한국어 해석]` — 비즈니스 맥락, 표제어(또는 변화형) 포함 |
| `rel` | 관련어 2~4개 `[단어, 뜻]` — 파생어·동의어·반의어·짝꿍 단어 |

JSON은 UTF-8, 따옴표는 `"`. 한국어 안의 인용은 `‘ ’` 를 쓴다(`"` 금지).

## 그림(SVG) 추가 지침 — 토익 단어

`scripts/viz/GUIDE.md` 가 기본이고, 토익 단어라 다음을 더 지킨다.

- 비즈니스 장면을 **사물·사람 실루엣·기호**로: 서류(가로줄 몇 개 그은 종이), 도장/서명(구불구불한 선), 계산서, 동전·지폐(원·사각형), 그래프 막대, 달력(격자), 시계, 상자·트럭·비행기, 건물, 악수, 말풍선(속은 비우거나 점 세 개), 체크/엑스, 화살표 등. **글자·숫자·통화 기호(₩ $) 금지** — 돈은 동전 원 + 반짝임 정도로.
- 사람은 단순한 원(머리) + 둥근 몸통 실루엣. 표정은 점·곡선으로만.
- 추상어(eligible, mandatory, tentative …)는 **뜻이 드러나는 사무실 상황**으로: 예) eligible = 조건 체크리스트가 모두 체크되자 문이 열림, tentative = 달력에 점선 동그라미 → 나중에 실선.
- 대표색 `data-c` 는 단어마다 골라도 되지만 너무 어둡지 않게.
- 모든 `id` 는 `<단어>_` 로 시작 (예: `invoice_clip`).

## 작업 순서 (배치 하나)

1. `scripts/viz/GUIDE.md` 를 끝까지 읽고, `scripts/viz/reference/` 의 SVG를 최소 4개 열어 본다.
2. 배치 파일의 단어마다 `viz/<단어>.svg` 와 `viz/<단어>.json` 을 만든다.
3. `node scripts/toeic-vocab/build.mjs --check <단어들…>` 를 돌려 **전부 통과할 때까지** 고친다.
   (SVG는 `scripts/validate-viz.mjs` 규칙, JSON은 위 형식, 그리고 steps 개수 = data-n 을 함께 검사한다.)
4. 자기 배치 단어 파일만 만든다. 다른 파일(특히 `public/learn/aboutMyVocab/`, `scripts/viz/`, `scripts/suneung/`)은 **절대 수정하지 않는다.** `build.mjs` 를 인자 없이 돌리지 않는다(마지막에 한 번만 돌림).
