# 수능 파트별 노트 콘텐츠 규격

`scripts/suneung/content/<이름>.mjs` 한 파일에 챕터 2~5개를 `export const chapters = [ ... ]` 로 내보낸다.
생성기(`scripts/generate-suneung-subjects.mjs`)가 이 객체를 HTML 페이지로 바꾼다. 코드 로직은 쓰지 않고 **내용 데이터만** 쓴다.

## 챕터 객체

```js
import { f, note, warn, tip, tbl, ex } from "../lib.mjs";

export const chapters = [
  {
    file: "01-exp-log.html",     // 정해 준 파일명 그대로
    part: "a1",                  // 정해 준 파트 ID (없으면 null)
    group: "수학Ⅰ",              // 사이드바 묶음 이름 (정해 준 값 그대로)
    unit: "수학Ⅰ",               // 헤더에 표시되는 단원명 (group과 같게 써도 됨)
    title: "지수와 로그",
    sub: "거듭제곱근 · 지수법칙 · 로그의 성질 · 지수함수와 로그함수",  // 한 줄 부제
    lead: `<p>…이 파트가 수능에서 어떻게 묻는지 2~4문장…</p>`,
    body: `<h2>1. …</h2> … `,   // 핵심 본문 (아래 규칙)
    traps: `<ul><li><strong>…</strong> …</li> … </ul>`,   // 자주 나오는 함정 5~8개
    examples: [ex("문제 한 줄", `<p>풀이</p>`), ex(…), ex(…)].join(""),  // 대표 예제 3~4개
    easy: `<h3>한 줄</h3><p>…</p><ul>…</ul>`,   // 쉬운 설명(비유·한 줄 정리)
    hard: `<p>…</p>`,                            // 고급(심화·풀이 순서)
    prompt: "…과 …를 짝지으세요.",
    pairs: [ { term: "…", def: "…" }, … ],      // 5~6개
    questions: [ { q: "…", choices: ["…","…","…","…"], answer: 1 }, … ],  // 정확히 5개, 보기 4개
  },
];
```

## 도우미 함수 (lib.mjs)
- `f(html)` : 공식 상자 `<div class="formula">…</div>` (줄바꿈은 `<br>`)
- `note(제목, html)` : 정보 카드. `warn(html)` : 함정 상자. `tip(html)` : 팁 상자.
- `tbl(머리행배열, 행배열)` : 표. 셀에는 HTML 가능.
- `ex(질문html, 풀이html)` : 눌러서 펼치는 예제.

## body 규칙
- `<h2>1. 절 제목</h2>` 로 절을 나눈다(4~6절). 필요하면 `<h3>` 소절. 표는 `tbl`, 공식은 `f`.
- 본문 전체 **최소 4500자**(공백 포함, 한글 1자=1). 물리학Ⅰ 챕터(`scripts/suneung/physics1.mjs`)보다 **더 자세하게** 쓴다: 정의 → 성질/공식 → 그림·그래프·표 읽는 법 → 수능에서 묻는 방식 순으로.
- 허용 태그: h2, h3, p, ul, ol, li, b, strong, em, sub, sup, span, table 계열(tbl 사용), div(도우미 함수가 만듦), details(ex가 만듦), br. 마크다운·인라인 스타일·이미지 금지.
- 수식은 HTML 첨자와 유니코드로: a<sub>n</sub>, x², √2, π, ∑, ∫, lim, →, ≤, ≥, ∞, ⁿ. 분수는 `a/b` 또는 `(a+b)/(2c)` 로.
- `<` `>` 는 본문에 그대로 쓰면 깨지므로 `&lt;` `&gt;` 로 쓴다(태그 제외).

## pairs / questions 규칙 (게임 엔진용)
- **일반 텍스트만**: HTML 태그·`&lt;` 같은 엔티티 금지. 수식은 유니코드(aₙ, x², √, π, →, ≥, ≤, ∞, ₀₁₂, ⁺⁻).
- pairs 5~6개, term과 def 모두 짧게(각 30자 이내 권장). 서로 헷갈리는 개념을 짝짓게 만든다.
- questions는 정확히 5개, 보기 4개(서로 다름), answer는 0~3의 정수. 정답 위치는 신경 쓰지 않아도 된다(생성기가 섞는다). 오답 보기는 실제로 수험생이 하는 착각으로 만든다.

## 내용 품질 기준
- **정확성이 최우선**이다. 2015 개정 교육과정, 2027학년도 수능까지의 범위만 다룬다. 범위 밖 내용은 넣지 않는다.
- 수치·계산 예제는 직접 풀어 검산한다. 확실하지 않은 사실(특정 연도 문항 번호, 통계, 출제 비율)은 쓰지 않는다. 출제 경향은 "자주 묻는다/단골" 같은 정성적 표현으로만.
- 각 챕터에 반드시 포함: 핵심 정의·공식, 그래프/표/그림을 읽는 방법, 수능형 문항이 묻는 방식, 자주 하는 착각(함정), 대표 예제 풀이.
- 기출 문항 지문을 그대로 옮기지 않는다(직접 만든 예제로). 문학·독서 작품은 제목·작가 정도만 언급하고 본문을 길게 인용하지 않는다(한 줄 이내).
- 학생 눈높이의 한국어. 존댓말(~입니다/~합니다) 문체로 통일한다.

## 검증
`node scripts/suneung/validate-chapters.mjs scripts/suneung/content/<이름>.mjs` 가 모두 통과해야 한다.
