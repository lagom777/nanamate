1. 네트워크 보안의 출발 — 계층과 경계

네트워크 보안은 OSI 7계층과 TCP/IP 4계층 위에서 데이터의 기밀성·무결성·가용성을 지키는 분야입니다. 각 계층마다 위협 모델과 통제 수단이 다릅니다: L2(스위치)에서는 ARP 스푸핑·MAC 플러딩, L3(라우터·IP)에서는 라우팅 하이재킹·IP 스푸핑, L4(TCP/UDP)에서는 SYN flood·세션 하이재킹, L7(애플리케이션)에서는 HTTP 기반 공격이 발생합니다.

전통적 보안 모델은 "성과 해자(castle & moat)"였습니다. 신뢰 가능한 내부망과 위험한 외부망을 방화벽으로 가르고, 내부는 자유 통행을 허용했죠. 그러나 클라우드·재택근무·SaaS가 보편화되면서 경계가 흐려졌고, 모든 트래픽을 검증하는 Zero Trust Network Access(ZTNA)로 패러다임이 이동하고 있습니다.

2. 방화벽과 IDS/IPS

방화벽은 정책에 따라 패킷을 허용·차단하는 장치입니다. 1세대는 정적 패킷 필터(소스/목적지 IP·포트 기반), 2세대는 상태 기반(stateful, TCP 연결 추적), 3세대는 차세대 방화벽(NGFW)으로 L7 검사·사용자 식별·위협 인텔리전스를 통합합니다.

IDS(Intrusion Detection System)는 의심 트래픽을 탐지·경보하고, IPS(Prevention)는 능동적으로 차단합니다. 탐지 방식은 ① 시그니처 기반(Snort, Suricata) — 알려진 패턴 매칭, ② 이상 기반(anomaly) — 정상 베이스라인 학습 후 편차 탐지, ③ 행위 기반(behavior) — 공격 행동 패턴 분석으로 나뉩니다. 시그니처는 신뢰도가 높지만 미지의 공격(zero-day)에 약하고, 이상 기반은 그 반대 트레이드오프입니다.

3. VPN — 안전한 터널

VPN(Virtual Private Network)은 공개 인터넷 위에 암호화된 터널을 만들어 사설망처럼 사용합니다. 사이트 간 VPN(branch ↔ HQ)과 원격 접속 VPN(개인 ↔ 회사)이 있고, 프로토콜은 IPsec(L3), OpenVPN/WireGuard(L4 위), TLS-기반 SSL VPN이 주로 쓰입니다.

WireGuard(2020년 리눅스 커널 5.6 통합)는 IPsec의 복잡성을 버리고 약 4,000줄의 코드로 구현된 차세대 VPN입니다. Curve25519·ChaCha20·Poly1305·BLAKE2s만 고정 사용하며, 핸드셰이크 1.5-RTT, 모바일 친화적 로밍을 지원합니다. 클라우드와 컨테이너 환경에서 사실상의 표준이 되었습니다. 다만 VPN은 만능 해결책이 아니며, Zero Trust 모델에서는 VPN 자체가 단일 실패 지점이 될 수 있어 ZTNA로 대체되는 추세입니다.

4. 패킷 분석과 트래픽 가시성

보안 사고 대응의 첫걸음은 "무슨 일이 일어났는지" 보는 것입니다. Wireshark·tcpdump·Zeek(구 Bro)는 패킷·플로우 분석의 표준 도구이며, 대규모 환경에서는 NetFlow/sFlow/IPFIX로 메타데이터만 집계해 효율성과 가시성을 균형 잡습니다.

현대 위협의 대부분은 TLS로 암호화되어 있어 페이로드 검사가 어렵습니다. 이를 위해 ① 기업 환경에서는 TLS 인터셉션(SSL 가시성, 합법적 MITM)을 쓰거나, ② 메타데이터 기반 탐지(JA3/JA4 핑거프린팅, ESNI/ECH 분석, 트래픽 패턴 분석)로 우회합니다. 다만 TLS 인터셉션은 프라이버시·법적 문제가 있어 사용 범위가 점차 축소되고 있습니다.

하 · 입문

한 줄로 이해하기

네트워크 보안은 "데이터가 컴퓨터 사이를 오갈 때 누가 훔쳐보거나 끼어들지 못하게" 지키는 일이에요. 방화벽이 출입통제, IDS/IPS가 CCTV·경비원, VPN이 비밀 전용 도로 역할을 합니다.

왜 중요한가?

① 회사 사무실에서만 접속되는 사내 시스템이 외부에서는 안 열리는 건 방화벽 덕분이에요. ② 카페 와이파이로 회사 이메일을 봐도 안전한 건 VPN이 만든 암호화 터널 때문. ③ "비정상 로그인 시도가 감지됐다"는 알림이 오는 건 IDS가 패턴을 발견해 알린 것입니다. 즉 우리가 "그냥 잘 동작하는" 네트워크 뒤에는 항상 이런 보안 장치들이 돌고 있어요.

🌱 핵심 용어

  • 방화벽(Firewall): 정해진 규칙대로 들어오는/나가는 트래픽을 허용·차단하는 장치
  • IDS / IPS: 의심 트래픽을 탐지(IDS)하거나 자동 차단(IPS)하는 시스템
  • VPN: 인터넷 위에 만든 암호화된 가상 전용선 — 카페 와이파이에서도 안전하게 회사망 접속
  • DDoS: 수많은 컴퓨터가 동시에 한 서버에 접속해 마비시키는 공격
  • Zero Trust: "내부망도 믿지 않는다" — 매 요청마다 신원을 재확인하는 새 패러다임

핵심 개념 풀어쓰기

회사 건물에 비유해봅시다. 방화벽은 정문의 출입게이트예요. 사원증이 있는 사람만 들여보내죠. IDS는 천장의 CCTV — 이상한 움직임이 보이면 경비실에 알립니다. IPS는 더 적극적인 경비원 — 의심스러우면 바로 막아요. VPN은 외근 중인 직원이 회사 안 자리에 앉은 것처럼 일하게 해주는 비밀 통로입니다. Zero Trust는 "회사 안에 있어도 매번 사원증을 다시 보여달라"고 요구하는 새로운 정책이에요.

💡 학습 TIP: "방화벽=문지기, IDS=감시카메라, IPS=경비원, VPN=비밀통로, Zero Trust=매번재확인" 이 다섯 비유만 박아두세요. 어떤 네트워크 보안 도구도 이 다섯 역할의 변형으로 이해할 수 있어요.

한 페이지 요약

  • 네트워크 보안 = 데이터 이동 중의 안전 확보
  • 방화벽 = 트래픽 허용·차단의 1차 관문
  • IDS는 탐지·경보, IPS는 능동 차단
  • VPN으로 공개 인터넷 위에 사설망 효과
  • Zero Trust = "내부도 안 믿는다", 현대의 새 표준
중 · 응용

이론 깊이 들어가기

방화벽의 진화는 트래픽 검사 깊이에 비례합니다. 1세대 패킷 필터는 5튜플(src/dst IP·포트, 프로토콜)만 검사하고 무상태이므로 응답 트래픽을 위한 양방향 규칙이 필요합니다. 2세대 stateful inspection은 연결 상태표(connection table)를 유지해 NEW/ESTABLISHED/RELATED를 구분합니다(Linux netfilter, BSD pf의 핵심). 3세대 NGFW는 DPI(Deep Packet Inspection)·애플리케이션 식별·사용자 인식·위협 인텔리전스 피드를 통합하며, Palo Alto·Fortinet·Check Point가 대표적입니다.

IDS/IPS의 핵심 지표는 탐지율과 오탐율의 트레이드오프입니다. 시그니처 기반 Suricata·Snort는 ET Open·Talos 같은 룰셋을 받아오며, 다중 스레딩과 하드웨어 오프로딩으로 10Gbps 이상 라인레이트 검사가 가능합니다. 행위/이상 기반 도구로는 Zeek가 사실상 표준이며, 스크립팅 가능한 프레임워크로 자체 탐지 로직을 작성할 수 있습니다.

핵심 코드 — iptables / nftables

# 1. 기본 정책: 들어오는 건 모두 차단 (whitelist 방식)
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 2. 루프백 + 기존 연결 허용
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. SSH(22) — 사내망에서만, 5분당 5회 시도 제한
iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/8 -m recent --set
iptables -A INPUT -p tcp --dport 22 -m recent --update --seconds 300 --hitcount 5 -j DROP

# 4. HTTPS(443) — 누구나 허용
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

🌐 예제 1 — 2016 Mirai 봇넷 DDoS

9월 KrebsOnSecurity는 620Gbps, 10월 Dyn DNS는 1.2Tbps의 DDoS를 받았습니다. 공격자는 디폴트 패스워드를 그대로 쓴 IoT 기기(CCTV·DVR) 수십만 대를 봇넷화했죠. 방어자는 ① BGP Anycast로 트래픽을 분산하고, ② Cloudflare·Akamai 같은 CDN의 스크러빙 센터로 우회하고, ③ ISP 수준 BCP38(소스 IP 검증)로 스푸핑을 차단합니다. 단일 호스트 방어로는 절대 막을 수 없다는 교훈을 남긴 사례입니다.

🌐 예제 2 — TLS 인터셉션과 한계

기업은 직원의 HTTPS 트래픽 내부 검사를 위해 내부 CA를 설치하고 프록시에서 인증서를 동적으로 발급합니다. 그러나 ① certificate pinning을 사용하는 모바일 앱은 깨지고, ② QUIC/HTTP3의 UDP+암호화는 인터셉션이 어렵고, ③ ECH(Encrypted Client Hello)가 보급되면 SNI 가시성도 사라집니다. 결국 메타데이터·DNS 가시성 위주의 탐지로 무게중심이 이동 중입니다.

응용 사례

① 마이크로세그멘테이션: VMware NSX, Cilium 같은 솔루션으로 워크로드 단위로 정책을 강제합니다. 한 컨테이너가 침해되어도 lateral movement가 차단됩니다. ② SD-WAN + SASE: 지점들을 인터넷 위에서 묶고, 보안(SWG·CASB·ZTNA·FWaaS)을 클라우드에서 일괄 제공하는 모델입니다. 가트너가 2019년 명명했고 Cisco·Zscaler·Cato가 주도합니다. ③ DNS 보안: DoT(DNS over TLS)·DoH(over HTTPS)로 쿼리 자체를 암호화하고, DNS 필터링(Quad9, Cloudflare 1.1.1.2, Pi-hole)으로 악성 도메인을 차단합니다.

⚠️ 자주 하는 실수: "방화벽만 잘 설정하면 안전하다"는 가정은 위험합니다. 현대 공격의 대부분은 ① 정상 트래픽처럼 보이는 HTTPS 위에서 일어나고, ② 합법 사용자 자격증명을 탈취해 정상 경로로 들어오며, ③ 내부에서 외부로 나가는 트래픽(C2 비콘, 데이터 유출)이 더 위험합니다. egress filtering과 행위 기반 탐지가 함께 필요합니다.
상 · 심화

전문가 레벨 이해

현대 네트워크 보안의 패러다임 전환은 NIST SP 800-207 (Zero Trust Architecture, 2020)에 정립되어 있습니다. 핵심 원칙은 ① 모든 데이터 소스·서비스를 자원으로 간주, ② 네트워크 위치와 무관하게 모든 통신을 보호, ③ 세션 단위로 접근 부여, ④ 클라이언트 신원·기기 상태·요청 컨텍스트를 종합한 동적 정책, ⑤ 모든 자산의 무결성·보안 상태를 측정·관찰, ⑥ 인증·인가는 매 요청 동적으로, ⑦ 가능한 한 많은 정보를 수집해 보안 자세를 개선. PDP(Policy Decision Point)와 PEP(Policy Enforcement Point) 분리는 SDN(Software-Defined Networking)의 control/data plane 분리와 구조적으로 유사합니다.

BGP 보안은 인터넷 라우팅의 약점입니다. 1989년 정의된 BGP는 신뢰 기반 프로토콜로, AS(Autonomous System) 간의 라우팅 광고를 검증하지 않습니다. 2018년 아마존 Route 53 하이재킹, 2008년 파키스탄 → YouTube 사고가 그 결과죠. 대응책으로 RPKI(Resource Public Key Infrastructure)가 IETF RFC 6480-6493에 정의되었고, ROA(Route Origin Authorization)와 BGPsec으로 광고를 암호화 검증합니다. 2025년 기준 IPv4 prefix의 약 50%가 ROA로 보호됩니다.

수학적·정량적 기초

$$\text{TCP throughput (Mathis): } BW \le \frac{\text{MSS}}{\text{RTT}} \cdot \frac{C}{\sqrt{p}}$$ $$\text{Erlang B (회선 차단확률): } B(c, A) = \frac{A^c/c!}{\sum_{k=0}^{c} A^k/k!}$$ $$\text{DDoS 증폭계수: } \text{AF} = \frac{\text{Response Size}}{\text{Request Size}} \quad (\text{NTP monlist} \approx 556\times,\; \text{Memcached} \approx 51{,}000\times)$$

DDoS 증폭공격의 핵심 수학은 위 증폭계수입니다. UDP 기반 무상태 프로토콜에서 소스 IP를 스푸핑하면, 응답이 피해자에게 폭주합니다. BCP38(RFC 2827, 1998)은 이 문제의 근본 해결책으로 ISP가 자기 네트워크에서 나가는 패킷의 소스 IP를 검증하라는 권고입니다. 그러나 deployment 인센티브가 없어 27년이 지난 지금도 완전 적용되지 않은 상태입니다.

최신 연구와 frontier

① QUIC와 HTTP/3: RFC 9000-9114로 표준화. UDP 위에서 TLS 1.3 통합, 0-RTT 재개, 연결 마이그레이션 등을 제공하며 2024년 기준 웹 트래픽의 30%+ 비중입니다. 보안 측면에서 패킷 번호 암호화로 트래픽 분석 저항성이 향상되었지만, 미들박스 가시성은 급감했습니다. ② eBPF 기반 관측·시행: Cilium·Tetragon이 커널 내부에서 syscall·socket 수준의 시행을 가능케 하여, 마이크로세그멘테이션과 런타임 위협 탐지의 성능 한계를 돌파하고 있습니다. ③ PQC migration: Cloudflare, Google이 2024년부터 X25519MLKEM768 하이브리드 키교환을 기본 활성화. 미래의 양자컴퓨터에 의한 retrospective decryption을 방지하기 위함입니다. ④ AI 기반 NIDS: Transformer·GNN을 활용한 트래픽 분류와 anomaly detection이 학술계 핫토픽이며, MIT/IBM의 Auto-IDS 같은 자동 룰 생성도 부상 중입니다.

관련 분야 연결

  • 분산시스템: BGP/AS 토폴로지, CAP 정리와 일관성, anycast 라우팅
  • 큐잉 이론: M/M/c 모델, 트래픽 폴리싱·쉐이핑, AQM
  • 그래프이론: 공격 그래프, attack tree, kill chain의 모델링
  • 제어이론: TCP 혼잡제어(BBR, CUBIC)의 안정성 분석
  • 경제학: deployment 인센티브 문제(BCP38, DNSSEC, RPKI의 적용률)
