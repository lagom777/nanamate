1. 암호학의 두 기둥 — 대칭·비대칭

암호학(Cryptography)은 정보를 비밀로 전달하고 위·변조 여부를 검증하기 위한 수학적 도구의 집합입니다. 현대 암호학은 크게 두 흐름으로 나뉩니다: 송수신자가 같은 키를 공유하는 대칭키 암호(Symmetric)와, 서로 다른 한 쌍의 키(공개키·개인키)를 쓰는 비대칭키 암호(Asymmetric, Public-Key)입니다.

대칭키 암호는 빠르지만 키 분배 문제가 어렵고, 비대칭키 암호는 키 분배는 우아하게 풀리지만 연산 비용이 큽니다. 실세계 프로토콜(TLS·SSH·메신저)은 둘을 결합한 하이브리드 암호화를 씁니다: 비대칭으로 세션키를 안전하게 교환한 뒤, 본문은 빠른 대칭키로 암호화하는 방식입니다.

3D · 암호화: 키 교환 → 암호화 → 전송 → 복호화
평문이 키를 통과해 섞이고 다시 풀리는 전 과정.

2. 해시 함수와 무결성

해시 함수는 임의 길이의 입력을 고정 길이 출력으로 압축하는 일방향 함수입니다. 안전한 해시 함수는 세 가지 성질을 만족해야 합니다: 원상 저항성(preimage), 제2 원상 저항성(second-preimage), 충돌 저항성(collision). MD5(1992)와 SHA-1(1995)은 충돌 저항성이 깨져 더는 보안 용도로 쓰지 않으며, 현재 표준은 SHA-256·SHA-3·BLAKE2 계열입니다.

해시는 단독으로는 무결성만 보장합니다. HMAC은 해시에 비밀키를 결합해 메시지 인증(MAC)을 제공하고, 디지털 서명은 비대칭 암호와 해시를 결합해 무결성·인증·부인 방지를 동시에 달성합니다.

3. 키 교환과 PKI

1976년 Diffie-Hellman의 키 교환 프로토콜은 도청자가 듣고 있는 공개 채널에서 두 당사자가 공유 비밀을 만들 수 있음을 보였습니다. 이산대수 문제의 어려움에 기반하며, 오늘날에는 타원곡선 위의 변형인 ECDH가 표준입니다(곡선 25519, P-256 등).

공개키를 누구의 것인지 검증하기 위해 공개키 기반구조(PKI)가 필요합니다. CA(인증기관)가 공개키와 신원을 묶어 X.509 인증서로 서명하고, 브라우저는 사전 신뢰하는 루트 CA들의 체인을 따라 검증합니다. Let's Encrypt(2016)의 등장과 ACME 프로토콜로 인증서는 무료·자동화되었고, 이제는 90일 단기 인증서가 표준이 되었습니다.

4. TLS — 인터넷의 기본 암호 계층

TLS(Transport Layer Security)는 인터넷의 모든 안전한 통신을 떠받치는 프로토콜입니다. TLS 1.3(2018)은 핸드셰이크를 1-RTT로 줄이고 알려진 취약 알고리즘(RC4·3DES·SHA-1·정적 RSA 키교환)을 모두 제거했습니다. 핵심 흐름은 ① ClientHello/ServerHello로 암호 스위트 협상, ② ECDHE로 일회용 세션키 교환, ③ 인증서 검증과 서버 인증, ④ AEAD 대칭암호(AES-GCM 또는 ChaCha20-Poly1305)로 본문 암호화 입니다.

TLS의 핵심 보안 속성은 전방향 안전성(Forward Secrecy)입니다. 서버의 장기 개인키가 미래에 유출되어도 과거 세션은 복호화할 수 없도록 매 세션마다 새로운 임시 키를 생성합니다. 이것이 정적 RSA 키교환이 폐기된 이유입니다.

하 · 입문

한 줄로 이해하기

암호학은 "남이 못 읽게 비밀로 만들기(암호화)", "내용이 바뀌었는지 확인하기(해시·서명)", "이 사람이 진짜 그 사람인지 확인하기(인증서)" 이 세 가지를 수학으로 푸는 학문이에요. 우리가 매일 쓰는 카카오톡·인터넷뱅킹·https 사이트가 다 이 위에 돌아갑니다.

왜 중요한가?

① 카페에서 와이파이로 인터넷뱅킹을 해도 누군가 훔쳐볼 수 없는 건 TLS라는 암호 프로토콜 덕분입니다. ② 카카오톡의 비밀채팅이 카카오 직원도 못 보는 건 종단간 암호화 때문이에요. ③ 윈도우 업데이트 파일이 진짜 마이크로소프트가 만든 것인지 확인하는 건 디지털 서명 덕분입니다. 즉, 우리가 매일 "당연하게" 누리는 디지털 안전은 전부 암호학 위에 서 있어요.

🌱 핵심 용어

  • 대칭키 암호: 자물쇠와 열쇠가 같은 종류 — 빠르지만 미리 키를 안전하게 주고받아야 함 (예: AES)
  • 비대칭키 암호: 자물쇠는 누구나 잠글 수 있고, 열쇠는 주인만 가짐 — 키 교환이 쉬움 (예: RSA, ECC)
  • 해시 함수: 어떤 데이터든 일정한 길이의 "지문"으로 줄여주는 함수 — 변조 감지에 사용 (예: SHA-256)
  • 디지털 서명: 종이 도장의 디지털 버전 — 내가 보냈다는 것과 내용이 안 바뀌었다는 것을 동시에 증명
  • 인증서(Certificate): "이 공개키는 진짜 네이버의 것"이라고 신뢰기관(CA)이 보증한 디지털 신분증

핵심 개념 풀어쓰기

편지를 안전하게 보내는 상황을 생각해봅시다. 대칭키 암호는 "둘만 아는 비밀 열쇠로 잠긴 상자"예요. 빠르고 튼튼하지만, 처음에 그 열쇠를 어떻게 상대에게 안전하게 보낼지가 문제입니다. 비대칭키 암호는 "누구나 잠글 수 있는 자물쇠와 나만 갖는 열쇠"입니다. 친구는 내가 미리 공개해둔 자물쇠로 편지를 잠그고, 나만 가진 열쇠로 풀어 읽어요. 키를 미리 공유할 필요가 없죠. 실제로는 "비대칭으로 한 번 잠시 쓸 대칭 열쇠를 안전하게 전달"하고, 그 다음부터는 빠른 대칭 암호로 대화하는 방식이 쓰입니다(하이브리드).

💡 학습 TIP: 외울 게 너무 많아 보이지만, "암호화는 비밀, 해시는 지문, 서명은 도장, 인증서는 신분증" 이 네 비유만 박아두면 거의 모든 암호 프로토콜이 이해됩니다.

한 페이지 요약

  • 대칭키 = 빠름, 키 분배 어려움 (AES)
  • 비대칭키 = 느림, 키 분배 쉬움 (RSA, ECC)
  • 해시 = 지문, 변조 감지 (SHA-256)
  • 디지털 서명 = 도장 + 지문 = 인증 + 무결성 + 부인방지
  • TLS = 위 모두를 묶어 인터넷에 적용한 표준
중 · 응용

이론 깊이 들어가기

대칭키 암호의 사실상 표준은 AES(2001, FIPS 197)입니다. 128/192/256비트 키, 128비트 블록의 SPN(Substitution-Permutation Network) 구조이며, 운용모드(Mode of Operation)에 따라 성격이 달라집니다. ECB는 같은 평문이 같은 암호문이 되어 절대 사용 금지이고, CBC는 IV 누수와 패딩 오라클에 취약합니다. 현재 표준은 인증암호화(AEAD)인 AES-GCM과 ChaCha20-Poly1305로, 기밀성과 무결성을 한 번에 제공합니다.

비대칭키 암호는 수학적 어려움(난문제)에 안전성을 의존합니다. RSA는 큰 정수의 소인수분해, DH/ECDH는 이산대수, ECDSA·Ed25519는 타원곡선 이산대수 문제에 기반합니다. 동등 보안 강도를 비교하면 RSA-2048 ≈ ECC-224 ≈ AES-112 수준이며, RSA-3072 ≈ ECC-256 ≈ AES-128입니다. 모바일·IoT 환경에서 ECC가 압도적으로 선호되는 이유입니다.

핵심 코드 — Python으로 보는 AEAD

# AES-GCM (cryptography 라이브러리)
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

key = AESGCM.generate_key(bit_length=256)
aesgcm = AESGCM(key)
nonce = os.urandom(12)              # GCM nonce는 반드시 96비트, 절대 재사용 금지
data = b"transfer $1000 to alice"
aad = b"account=bob, timestamp=2025-05-20"  # 인증만 하고 암호화는 안 하는 부가 데이터

ct = aesgcm.encrypt(nonce, data, aad)
pt = aesgcm.decrypt(nonce, ct, aad)  # aad가 바뀌면 InvalidTag 예외
assert pt == data

대표 예제

🔐 예제 1 — Signal 프로토콜의 더블 래칫

WhatsApp·시그널의 종단간 암호화는 X3DH(Extended Triple Diffie-Hellman) 키 합의 + Double Ratchet 알고리즘 조합입니다. 매 메시지마다 새로운 키가 파생되어, 한 키가 노출되어도 이전·이후 메시지는 안전합니다(forward secrecy + post-compromise security). 단순한 "AES로 암호화"가 아니라 키 관리가 핵심임을 보여주는 사례입니다.

🔐 예제 2 — HTTPS 인증서 검증

브라우저가 https://naver.com에 접속할 때, 서버가 보낸 인증서 체인을 검증합니다. ① 인증서의 서명을 상위 CA의 공개키로 검증 → ② 그 상위 CA도 같은 방식으로 → ③ 최상위 루트 CA에 도달 (브라우저에 사전 탑재). 추가로 ④ 도메인 이름(SAN) 일치, ⑤ 유효기간, ⑥ OCSP/CRL로 폐기 여부 확인, ⑦ Certificate Transparency 로그에 등록되었는지까지 봅니다. 어느 하나라도 실패하면 빨간 경고 화면이 뜹니다.

응용 사례

① JWT(JSON Web Token)는 HMAC-SHA256(대칭) 또는 RSA·ECDSA(비대칭) 서명으로 토큰의 무결성과 발급자를 보장합니다. 'alg: none' 취약점이나 약한 키 사용은 자주 발견되는 사고 원인입니다. ② 비밀번호 저장은 단순 SHA-256이 아니라 bcrypt·scrypt·Argon2 같은 의도적으로 느린 KDF를 써야 합니다. 2023년 NIST는 Argon2id를 권장합니다. ③ 파일 서명: GPG, code signing, sigstore 등은 모두 비대칭 서명의 응용입니다.

⚠️ 자주 하는 실수: "암호학은 직접 구현하면 안 된다(Don't roll your own crypto)"는 격언이 가장 중요합니다. AES 자체는 안전해도 ECB 모드를 쓰거나, IV/Nonce를 재사용하거나, 비상수시간(non-constant-time) 비교로 키를 누수하거나, 약한 난수원을 쓰면 전부 무력화됩니다. 검증된 라이브러리(libsodium, BoringSSL, Tink)를 쓰세요.
상 · 심화

전문가 레벨 이해

현대 암호학의 안전성 정의는 증명가능 보안(provable security) 패러다임에 기반합니다. 어떤 암호 스킴 $\Pi$가 안전하다는 것은, 임의의 다항시간 적대자 $\mathcal{A}$의 성공 확률을 어떤 수학적 난문제(소인수분해·이산대수·LWE 등)를 푸는 알고리즘으로 환원(reduction)할 수 있음을 보이는 것입니다. 예: IND-CPA, IND-CCA2, EUF-CMA 같은 게임 기반 정의를 통해 적대자 모델을 형식화합니다.

대칭키 영역의 최신 흐름은 경량 암호(Lightweight Cryptography)입니다. NIST는 2023년 IoT·임베디드용 표준으로 Ascon을 선정했습니다. AES-GCM보다 메모리·전력 효율이 우수하면서도 충분한 보안 마진을 가집니다.

수학적 기초

$$\text{RSA: } c = m^e \bmod n, \quad m = c^d \bmod n, \quad ed \equiv 1 \pmod{\phi(n)}$$ $$\text{ECDH: } K_{AB} = a \cdot (b \cdot G) = b \cdot (a \cdot G) \in E(\mathbb{F}_p)$$ $$\text{HKDF: } \text{PRK} = \text{HMAC}(\text{salt}, \text{IKM}), \quad \text{OKM} = \text{HMAC-Expand}(\text{PRK}, \text{info}, L)$$

RSA의 안전성은 $n = pq$의 소인수분해 어려움에 환원되며, 일반수체체(GNFS)의 점근 복잡도는 $\exp((c+o(1))(\ln n)^{1/3}(\ln\ln n)^{2/3})$입니다. ECDLP는 일반 군에서 $\Omega(\sqrt{n})$의 Pollard rho 공격이 알려진 최선이므로, 같은 안전 강도에서 훨씬 작은 키 크기로 충분합니다.

최신 연구와 frontier

① Post-Quantum Cryptography (PQC): 충분히 큰 양자컴퓨터가 등장하면 Shor 알고리즘으로 RSA·ECC가 다항시간에 깨집니다. NIST는 2024년 8월 ML-KEM(FIPS 203, Kyber 기반 격자 KEM), ML-DSA(FIPS 204, Dilithium 기반 서명), SLH-DSA(FIPS 205, SPHINCS+ 해시 기반 서명)을 표준화했고, 2025년부터 주요 CA·CDN·OS가 마이그레이션을 시작했습니다. Harvest now, decrypt later 위협 때문에 장기 기밀성이 필요한 데이터는 지금 PQC 하이브리드로 전환해야 합니다. ② 완전동형암호(FHE): Microsoft SEAL, OpenFHE, Zama Concrete 등의 라이브러리로 암호화된 상태로 연산이 가능하며, 의료 데이터·금융 분석에 응용 중입니다. ③ 영지식 증명(ZKP): zk-SNARK·zk-STARK는 블록체인 롤업과 프라이버시 보호 신원 증명(zkLogin, Anon Aadhaar)에 실용 단계로 진입했습니다.

관련 분야 연결

  • 수론: 소인수분해, 이산대수, 타원곡선의 군 구조
  • 대수기하학: 격자 이론(LWE, NTRU), 동조사상(Isogeny) 기반 암호
  • 복잡도 이론: PRG·PRF·OWF의 동등성과 minimal assumption
  • 분산시스템: 비잔틴 합의, 임계 서명(threshold signature), MPC
  • 양자정보: BB84·E91 양자 키 분배, Shor·Grover 알고리즘
