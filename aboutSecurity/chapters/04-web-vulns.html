1. OWASP Top 10 — 웹 보안의 공식 지도

OWASP(Open Worldwide Application Security Project)는 2003년부터 웹 애플리케이션의 가장 치명적이고 빈번한 보안 위협을 3~4년마다 갱신해 발표하는 비영리 단체입니다. 가장 최근판인 OWASP Top 10 (2021)는 50만 개 이상의 실제 애플리케이션 데이터와 산업 설문을 종합해 만들어졌으며, 사실상 웹 보안의 공통 언어입니다.

2021년판 순위는 ① A01 Broken Access Control, ② A02 Cryptographic Failures, ③ A03 Injection, ④ A04 Insecure Design, ⑤ A05 Security Misconfiguration, ⑥ A06 Vulnerable and Outdated Components, ⑦ A07 Identification and Authentication Failures, ⑧ A08 Software and Data Integrity Failures, ⑨ A09 Security Logging and Monitoring Failures, ⑩ A10 Server-Side Request Forgery입니다. 이전에 독립 항목(2017 A7)이었던 XSS는 Injection 카테고리에 흡수되었습니다.

2. A01 — Broken Access Control

접근 통제 결함은 2021년 OWASP Top 10에서 5위에서 1위로 급상승했습니다. 실제 침해 사건의 가장 빈번한 원인이며, IDOR(Insecure Direct Object Reference), 권한 우회, 강제 브라우징, JWT 변조 등이 포함됩니다.

대표 패턴은 GET /api/users/123/orders를 GET /api/users/124/orders로 바꿔 남의 데이터를 보는 IDOR입니다. 단순히 URL의 ID만 바꾸면 되니 자동화 공격이 쉽고, 피해 규모가 큽니다. 해결책은 ① 매 요청마다 서버에서 현재 사용자와 자원 소유자의 일치를 검증, ② 가능한 한 식별자는 추측 불가능한 UUID·암호학적 토큰 사용, ③ 권한 모델을 코드 전반에 일관되게 적용하는 권한 라이브러리·미들웨어 도입입니다.

3. A03 — Injection (SQLi, NoSQLi, XSS, 명령어 주입)

Injection은 신뢰할 수 없는 데이터가 인터프리터(SQL, OS shell, LDAP, XML, NoSQL 쿼리, 브라우저 DOM)에 명령으로 해석될 때 발생합니다. SQL Injection은 1998년 Rain Forest Puppy의 공개 이후 27년이 지난 지금도 매년 침해 사고의 단골입니다. XSS(Cross-Site Scripting)는 사용자 입력이 다른 사용자의 브라우저에서 JavaScript로 실행되는 형태이며, Reflected · Stored · DOM-based로 분류됩니다.

방어의 근본 원칙은 단순합니다: "데이터와 코드를 분리하라". SQL은 prepared statement(parameterized query)로, 셸 명령은 인자 배열 전달로, HTML 출력은 컨텍스트 인식 인코딩으로 처리합니다. CSP(Content Security Policy) 헤더는 XSS의 영향을 추가로 격리합니다.

4. A10 — SSRF, 그리고 클라우드 시대의 새 위협

SSRF(Server-Side Request Forgery)는 서버가 공격자가 지정한 URL로 요청하게 만드는 취약점입니다. 2019년 Capital One 침해(1억 명 개인정보)의 직접 원인이었으며, AWS·GCP·Azure의 메타데이터 엔드포인트(http://169.254.169.254/)에 접근해 IAM 자격증명을 탈취하는 형태가 대표적입니다.

클라우드 환경에서는 SSRF가 단순한 내부망 스캔이 아니라 권한 상승 + 데이터 탈취의 출발점이 됩니다. 방어책은 ① IMDSv2(토큰 기반) 강제, ② 메타데이터 엔드포인트에 대한 egress 차단, ③ URL 파싱·DNS 재해석(rebinding) 방어, ④ 외부 요청 전용 프록시를 통한 일원화된 통제입니다.

한 줄로 이해하기

웹 사이트가 해킹되는 거의 모든 경로는 ① 남의 정보를 그냥 봐버리거나(접근 통제 실패), ② 입력에 슬쩍 코드를 끼워 넣거나(인젝션), ③ 비밀번호를 약하게 두거나, ④ 설정을 잘못 한 데서 옵니다. OWASP Top 10은 그 10가지 가장 흔한 실수를 정리해둔 체크리스트예요.

왜 중요한가?

① 페이스북·트위터 같은 거대 서비스가 매년 보안 사고를 내는 이유는 OWASP Top 10에 다 적혀 있어요. ② 내가 만든 자그마한 토이 프로젝트라도 이 10가지만 점검하면 흔한 자동 스캔 공격의 80% 이상을 막을 수 있습니다. ③ 보안 면접·자격증(Security+, CISSP)에서 거의 빠지지 않는 주제이기도 해요.

🌱 핵심 용어

  • OWASP: 웹 보안 가이드를 무료로 공개하는 비영리 단체. Top 10 외에도 ASVS, Cheat Sheet 시리즈가 유명
  • 접근 통제(Access Control): 누가 무엇을 볼·수정·삭제할 수 있는지 결정하는 규칙
  • 인젝션(Injection): 입력칸에 명령어를 끼워 넣어 서버를 속이는 공격 (SQLi, XSS 등)
  • SSRF: 서버를 시켜 다른 곳에 요청하게 만들기 — 내부망 탐색·자격증명 탈취에 사용
  • CSP: 브라우저에 "이 사이트에선 이런 출처의 스크립트만 실행해도 돼"라고 알려주는 헤더

핵심 개념 풀어쓰기

가게에 비유해봅시다. 접근 통제 결함은 직원만 들어가야 할 창고 문이 활짝 열려 있는 상황이에요. 인젝션은 손님이 주문서에 "음료 주세요. 그리고 금고를 열어주세요"라고 적었는데 점원이 그걸 그대로 실행해버리는 거죠. SSRF는 가게 직원에게 "옆 가게에 가서 비밀번호 좀 알아와 주세요"라고 시키는 거예요. 다 사람이라면 안 속겠지만 컴퓨터는 매뉴얼에 없으면 그냥 따릅니다.

한 페이지 요약

  • OWASP Top 10 = 웹 사고의 가장 흔한 10가지 원인 카테고리
  • 2021년판 1위 = Broken Access Control (남의 데이터 접근)
  • 3위 = Injection — "데이터와 코드를 분리"가 만병통치 원칙
  • 10위 = SSRF — 클라우드 시대에 치명적
  • 방어는 사후 패치보다 설계 단계 점검이 압도적으로 효율적
중 · 응용

이론 깊이 들어가기

OWASP Top 10은 단순 순위가 아니라 CWE(Common Weakness Enumeration) 매핑입니다. 2021년판 A01에는 CWE-22(Path Traversal), CWE-284(Improper Access Control), CWE-352(CSRF) 등 34개 CWE가 포함됩니다. CWE → CVE(특정 제품 취약점) → CVSS(점수) → KEV(Known Exploited Vulnerabilities, CISA 운영)로 이어지는 체인이 현대 취약점 관리의 표준 어휘입니다.

SQL Injection의 변형은 시간이 지나며 정교해졌습니다. ① Classic union-based, ② Blind boolean-based, ③ Time-based blind, ④ Out-of-band(DNS/HTTP exfil), ⑤ Second-order(저장 후 다른 쿼리에서 실행). sqlmap은 이 모든 패턴을 자동화하며, WAF 우회 기법(인코딩, 주석, 함수 호출)도 내장합니다. 방어는 prepared statement가 우선이지만, ORM 사용 시에도 raw query·dynamic order by·LIKE 패턴에는 별도 검증이 필요합니다.

핵심 코드 — 안전한 입력 처리

# 🚫 위험 — f-string으로 SQL 조립 (SQLi 직격탄)
cursor.execute(f"SELECT * FROM users WHERE email = '{email}'")

# ✅ 안전 — prepared statement
cursor.execute("SELECT * FROM users WHERE email = %s", (email,))

# 🚫 위험 — 사용자 입력을 그대로 셸에 전달
import os
os.system(f"convert {filename} out.png")

# ✅ 안전 — 인자 배열 + 쉘 우회
import subprocess
subprocess.run(["convert", filename, "out.png"], check=True, shell=False)

# 🚫 위험 — XSS (사용자 입력을 HTML에 직접 삽입)
response.write(f"<div>안녕하세요 {name}님</div>")

# ✅ 안전 — 컨텍스트 인식 이스케이프 (Jinja2, React 등은 기본 적용)
from markupsafe import escape
response.write(f"<div>안녕하세요 {escape(name)}님</div>")

대표 예제

🕷️ 예제 1 — 2019 Capital One 침해

한 전직 AWS 엔지니어가 Capital One의 WAF 설정 오류(SSRF 방어 미흡)를 이용해 EC2 인스턴스의 IAM 메타데이터를 탈취, 약 1억 명의 개인정보와 신용카드 신청 데이터를 유출했습니다. 핵심 결함은 ① WAF 룰이 outbound 요청을 충분히 검사하지 못함, ② IMDSv1 사용으로 토큰 없이 자격증명 발급, ③ 해당 IAM 역할에 과도한 S3 권한 부여. 단일 SSRF가 권한상승·데이터유출까지 단번에 연결된 교과서적 사례입니다.

🕷️ 예제 2 — Stored XSS와 워밍

2005년 MySpace의 'Samy 웜'은 프로필 페이지에 저장된 XSS를 통해 24시간 만에 100만 명 이상을 감염시켰습니다. 방문자의 프로필 페이지에 친구추가·웜 코드를 자동 삽입하는 자기 복제 코드였죠. 이후 OWASP Cheat Sheet의 XSS 방어 권고는 ① 출력 컨텍스트별 인코딩(HTML/Attr/JS/CSS/URL), ② CSP 헤더(script-src 'self'), ③ HttpOnly+Secure 쿠키, ④ Trusted Types(브라우저 신 표준)의 4단계 방어로 진화했습니다.

응용 사례

① WAF(Web Application Firewall): AWS WAF, Cloudflare, ModSecurity + OWASP CRS는 시그니처·룰 기반 방어. 우회 가능성 때문에 보조 수단으로만 의존해야 합니다. ② SAST·DAST·IAST: 정적분석(Semgrep, CodeQL), 동적분석(ZAP, Burp Suite), 인스트루먼테이션 기반(Contrast Security) — 개발 파이프라인에 통합. ③ SCA(Software Composition Analysis): Snyk, Dependabot, Trivy — A06 Vulnerable Components 대응. ④ CSP nonce/hash로 인라인 스크립트 차단, ⑤ SRI(Subresource Integrity)로 CDN 자원 변조 방지.

⚠️ 자주 하는 실수: ① WAF만 믿고 코드 검증을 소홀히 하기, ② "프레임워크가 알아서 막아주겠지" — 실제로는 raw query·dangerouslySetInnerHTML·eval 등이 곳곳에 있음, ③ blacklist 기반 입력 검증(공격 패턴을 막는 방식)은 거의 항상 우회됨 — 반드시 allowlist로, ④ 에러 메시지에 SQL 쿼리·스택 트레이스 노출 — 공격자에게 시스템 구조를 알려주는 셈.
상 · 심화

전문가 레벨 이해

OWASP Top 10의 한계도 인식해야 합니다. ① 카테고리가 너무 광범위해 구체 가이드로는 부족, ② 데이터 출처 편향(설문 + 공개 데이터셋만), ③ API와 모바일 환경의 새로운 위협 부족 — 이를 보완하기 위해 OWASP API Security Top 10 (2023), OWASP Mobile Top 10, OWASP LLM Top 10 (2023, v2.0 2025)이 별도로 발표되었습니다.

특히 OWASP ASVS(Application Security Verification Standard) v5.0 (2024)는 Top 10보다 훨씬 세부적인 검증 체크리스트(약 300개)를 Level 1(최소)/2(표준)/3(고위험) 단계로 제공합니다. 실제 보안 감사·인증의 표준 도구이며, NIST SP 800-218(SSDF)과 매핑됩니다. SAMM(Software Assurance Maturity Model)은 조직 차원의 보안 성숙도 측정 프레임워크로 거버넌스·설계·구현·검증·운영의 5도메인 15실천으로 구성됩니다.

수학적·정량적 기초

$$\text{CVSS Base} = \text{Roundup}(\min[1.08 \times (\text{Impact} + \text{Exploitability}), 10])$$ $$\text{EPSS Score} = P(\text{exploit observed in next 30 days} \mid \text{CVE features})$$ $$\text{Risk Score (FAIR)} = \text{LEF} \times \text{Magnitude}, \quad \text{LEF} = \text{TEF} \times \text{Vulnerability}$$

EPSS(Exploit Prediction Scoring System)는 FIRST.org가 운영하는 ML 기반 익스플로잇 가능성 예측 모델로, 매일 갱신됩니다. CVSS의 정적 심각도와 결합해 패치 우선순위를 결정하는 것이 2024년 이후의 표준 패턴입니다. CVSS 9+ 중에서도 EPSS 0.05 이상인 약 5%만이 실제로 30일 내 익스플로잇되며, 이 작은 부분에 자원을 집중하는 것이 자원 효율적입니다.

최신 연구와 frontier

① OWASP LLM Top 10 v2.0 (2025): Prompt Injection(직간접), Insecure Output Handling, Training Data Poisoning, Model DoS, Supply Chain, Sensitive Info Disclosure, Insecure Plugin Design, Excessive Agency, Overreliance, Model Theft. AI 에이전트의 도구 사용 권한이 핵심 신규 위협. ② Supply Chain Security: SLSA(Supply-chain Levels for Software Artifacts) 1.0이 2023년 GA, in-toto / sigstore / cosign으로 빌드·서명·검증이 표준화됨. xz-utils 백도어(2024) 사건이 결정적 계기. ③ Web Authentication: WebAuthn/Passkeys가 password-less의 사실상 표준으로 자리잡았고, Apple·Google·Microsoft가 cross-device 동기화 제공. ④ Browser security primitives: COOP, COEP, CORP로 Spectre·Meltdown 후속 사이드채널 방어; Trusted Types로 DOM-XSS 원천 차단; Origin Trial로 신기능 점진 배포.

관련 분야 연결

  • 컴파일러·언어 이론: taint analysis, abstract interpretation을 활용한 SAST
  • 형식 검증: Boogie, Dafny, F* 등으로 인가 로직의 안전성 증명
  • 분산시스템: 분산 트랜잭션과 권한 일관성, capability-based security
  • UX/HCI: 보안 결정 UI의 인지부담 — 동의 화면 피로(consent fatigue)
  • 법학: GDPR Article 25(default 보안), 침해 통지 의무, 책임 분배
