1. 사고 대응이 필요한 이유

아무리 잘 방어해도 보안 사고는 일어납니다. 2024년 IBM Cost of a Data Breach 보고서는 평균 침해 비용을 $4.88M, 평균 식별·억제 시간을 277일로 보고합니다. 사고 대응(Incident Response, IR)은 일이 터졌을 때 피해를 최소화하고 빠르게 정상화하기 위한 사전 정의된 프로세스입니다.

IR의 핵심 가치는 "준비된 조직과 안 준비된 조직"의 차이를 만드는 것입니다. 같은 침해라도 IR 플레이북·연락망·법적 자문이 미리 준비된 조직은 시간당 손실을 1/10까지 줄일 수 있고, 사후 규제 대응에서도 큰 차이가 납니다. NIST SP 800-61(Computer Security Incident Handling Guide)과 SANS의 PICERL 모델이 사실상의 표준 프레임워크입니다.

3D · 사고 대응: 봉쇄가 핵심인 6단계
랜섬웨어 사고가 수습되는 전 과정.

2. PICERL — 사고 대응 6단계

SANS가 정립한 PICERL은 ① Preparation(준비) — 플레이북, 도구, 권한, 연락망, ② Identification(식별) — 알람 트리아지, IoC 매칭, 정상/사고 구분, ③ Containment(격리) — 단기(네트워크 차단)와 장기(이미지 재생성), ④ Eradication(제거) — 멀웨어 제거, 백도어 차단, 자격증명 회수, ⑤ Recovery(복구) — 단계적 서비스 복귀, 모니터링 강화, ⑥ Lessons Learned(교훈) — 사후 회의, 통제 개선, 플레이북 갱신.

가장 자주 실수하는 단계는 ③ 격리와 ⑥ 교훈입니다. ③은 너무 일찍 격리하면 공격자에게 발각된 사실을 알려 데이터 파괴를 유발하고, 너무 늦으면 피해가 확산됩니다. ⑥은 사고가 끝나면 "안도감"으로 분석을 미루는 인간 본성과 싸워야 합니다. blameless postmortem 문화가 핵심입니다.

3. 디지털 포렌식의 원칙과 흐름

디지털 포렌식은 사고의 "무엇이 일어났는가"를 법적·기술적으로 검증 가능하게 재구성하는 학문입니다. 4대 원칙은 ① 증거 보존(원본 변경 금지), ② 연속성(Chain of Custody), ③ 재현성, ④ 전문성·중립성입니다. 법정 증거로 인정받으려면 모든 단계가 문서화되어야 합니다.

표준 흐름은 ① 수집(Acquisition) — write blocker로 디스크 비트 단위 복제(dd, FTK Imager), 메모리 덤프(WinPmem, AVML), ② 보존(Preservation) — SHA-256 해시로 무결성 봉인, ③ 분석(Examination) — Autopsy/EnCase/X-Ways로 파일시스템·아티팩트 분석, Volatility로 메모리, Plaso로 타임라인, ④ 보고(Presentation) — 비전문가도 이해 가능한 서술 + 기술 부록입니다.

4. 휘발성 순서와 메모리 포렌식

증거의 휘발성 순서(Order of Volatility, RFC 3227)는 ① CPU 레지스터·캐시 → ② RAM → ③ 네트워크 연결·라우팅 → ④ 디스크 → ⑤ 원격 로그 → ⑥ 미디어 백업 → ⑦ 물리 구성 순입니다. 휘발성이 높을수록 먼저 수집해야 합니다. 시스템을 무작정 끄면 메모리만 알 수 있는 결정적 증거(C2 연결, 복호화 키, fileless payload)가 사라집니다.

메모리 포렌식의 가치는 막대합니다. ① 실행 중 프로세스와 부모-자식 트리(pslist/pstree), ② 숨겨진 프로세스(psxview), ③ 코드 인젝션 탐지(malfind), ④ 네트워크 연결(netscan), ⑤ 로그된 사용자(hashdump), ⑥ 사용자가 입력한 명령 이력(cmdline/consoles). Volatility 3, MemProcFS는 사실상의 표준 도구입니다.

한 줄로 이해하기

사고 대응은 "해킹이 터졌을 때 119처럼 출동하는 절차"이고, 포렌식은 "범죄 현장 감식처럼 컴퓨터 안 흔적으로 무슨 일이 있었는지 재구성"하는 일이에요. 두 가지가 짝이 되어, 사고를 빨리 끊고 같은 일이 다시 안 일어나게 만듭니다.

왜 중요한가?

① 카드회사가 침해됐다는 뉴스가 나오면, 사실 그 회사는 IR팀이 가동 중이에요. ② 영화 'CSI'의 감식 같은 게 진짜 컴퓨터에도 있고요. ③ 개인적으로도 랜섬웨어 걸렸을 때 패닉으로 PC를 끄면 메모리만 알 수 있던 복호화 키가 날아갑니다. 즉 "끌까 말까"부터가 사고 대응의 첫 결정이에요.

🌱 핵심 용어

  • IR(Incident Response): 사고 대응 — 침해가 일어났을 때 따라야 하는 정해진 순서
  • 플레이북(Playbook): 시나리오별 대응 매뉴얼 — 랜섬웨어, 피싱, DDoS 등 미리 작성
  • IoC(Indicator of Compromise): 침해의 흔적 — 악성 IP, 파일 해시, 도메인 등
  • 포렌식: 컴퓨터에 남은 흔적을 분석해 사건 재구성
  • Chain of Custody: 증거 인수인계 기록 — 법정 인정의 핵심
  • 휘발성 순서: 빨리 사라지는 것부터 수집 — 메모리 먼저, 디스크 나중

핵심 개념 풀어쓰기

화재에 비유하면 사고 대응은 ① 화재 감지·신고, ② 대피와 구획화(불이 다른 층으로 안 가게), ③ 진화, ④ 잔불 정리, ⑤ 복구, ⑥ 원인 조사·재발 방지의 6단계입니다. 포렌식은 마지막 단계의 원인 조사예요 — 어디서 어떻게 시작됐는지, 누구의 잘못이 아니라 시스템의 어디가 약했는지를 밝힙니다. blameless 문화가 중요한 이유는, 잘못한 사람을 찾으면 다음 사고 때 사람들이 숨기기 때문이에요.

💡 학습 TIP: 개인 차원에서도 미니 IR 플레이북을 만들어두세요: ① 의심 시 인터넷부터 끊기(랜선·와이파이 OFF), ② 즉시 끄지 말기(메모리 보존), ③ 비밀번호 전원 변경(다른 깨끗한 기기에서), ④ 백업으로 복원, ⑤ 사후 검토. 이 5단계만 머릿속에 있어도 큰 차이가 납니다.

한 페이지 요약

  • 사고 대응 = 사고 발생 시 표준 절차 (PICERL 6단계)
  • 준비된 조직은 피해를 1/10까지 줄임
  • 포렌식 = 디지털 증거 수집·분석으로 사건 재구성
  • 증거는 휘발성 순으로 — 메모리부터 보존
  • blameless postmortem이 조직 학습의 핵심
  • NIST SP 800-61이 IR 가이드의 정석
중 · 응용

이론 깊이 들어가기

현대 IR의 가장 큰 변화는 SIEM → SOAR → XDR 자동화 체인입니다. SIEM(Splunk, Elastic, Microsoft Sentinel)이 다중 소스 로그를 상관관계 분석하고, SOAR(Tines, XSOAR, Shuffle)가 정해진 플레이북을 자동 실행합니다. "피싱 의심 메일 신고 → URL/첨부 sandboxing → 동일 메일 받은 전 사용자 식별 → 격리 → 사용자 알림 → 티켓 생성"을 사람 개입 없이 5분 안에 마칠 수 있습니다.

로그 정합성과 시간 동기화는 포렌식의 토대입니다. NTP 동기화가 깨진 시스템들의 로그는 타임라인 재구성에서 거의 무용지물이 됩니다. UTC 기준 저장, 호스트별 타임스탬프 보존, monotonic clock 활용, 로그 변조 방지(append-only, WORM, syslog 원격 전송)가 필수입니다. 2024년부터 macOS·Windows는 unified logging으로 통합되었고, 리눅스는 journald + remote shipping이 표준입니다.

핵심 도구 — Volatility로 메모리 분석

# 1. 메모리 수집 — WinPmem (Windows) 또는 AVML (Linux)

# 2. Volatility 3 — 프로세스 트리 / 의심 인젝션

vol -f memory.raw windows.pstree
vol -f memory.raw windows.malfind

# 3. 네트워크 연결 / 자격증명 / 명령 이력
vol -f memory.raw windows.netscan
vol -f memory.raw windows.hashdump
vol -f memory.raw windows.cmdline

# 4. 파일시스템 타임라인 — Plaso (log2timeline)

대표 예제

🚨 예제 1 — 2017 NotPetya와 Maersk

러시아 군정보국이 우크라이나 회계 소프트웨어 M.E.Doc 업데이트를 무기화한 wiper 공격이 전 세계로 확산. Maersk는 4만 5천 대 PC, 4천 대 서버가 마비됐고, 도메인 컨트롤러 154개 중 살아남은 단 1대(가나 지사가 정전으로 꺼져 있었음)로 AD 전체를 복구했습니다. 피해 약 $3억. 교훈: 백업과 복구 계획은 "전 세계 동시 wiper" 시나리오도 가정해야 합니다.

🚨 예제 2 — 랜섬웨어 IR 표준 흐름

① 영향 범위 파악(어느 호스트가 암호화 시작했는가, 횡적 확산은?) → ② 네트워크 분리(VLAN 차단, EDR isolate) → ③ 메모리·디스크 이미지 확보 → ④ 다크웹·KNOWN 그룹 분석(Mandiant/SentinelOne IOC 매칭) → ⑤ 백업 무결성 확인(공격자가 백업을 먼저 지운 경우 多) → ⑥ 단계적 복구 + 자격증명 전수 회수 → ⑦ 외부 신고(KISA, 보험, 규제) → ⑧ post-incident review.

응용 사례

① EDR 기반 IR: CrowdStrike Real Time Response, Defender Live Response로 원격 cmd·파일수집·격리. ② Cloud Forensics: AWS GuardDuty + Detective, Azure Sentinel + Defender for Cloud, GCP SCC. EC2 snapshot으로 즉시 evidence preservation. ③ Memory-only IR: Velociraptor, GRR로 대규모 endpoint에서 동시 hunting. ④ SOAR 플레이북: Shuffle/Tines 무료 옵션, 자동화로 SOC 분석가 작업 50%+ 절감.

⚠️ 자주 하는 실수: ① 사고 의심 시 즉시 종료 → 메모리 증거 손실. ② 자격증명 변경 없이 복구 → 공격자가 즉시 재침투. ③ 백업이 같은 도메인 안에 있어 공격자가 미리 삭제. ④ "감사 로그가 너무 많아 비활성화" → 사고 시 알 수가 없음. ⑤ 외부 노출(언론 발표) 전에 법무·홍보 검토 누락 → 2차 사고. ⑥ post-incident review를 안 함 → 같은 사고 반복.
상 · 심화

전문가 레벨 이해

현대 DFIR(Digital Forensics & Incident Response)의 패러다임은 "single endpoint deep dive"에서 "fleet-wide hunting"으로 이동했습니다. Velociraptor(Rapid7 후원, 오픈소스)는 VQL(Velociraptor Query Language)로 수만 대 endpoint에 동시 hunt를 발사하고 결과를 중앙 집계합니다. "현재 모든 호스트에서 Cobalt Strike beacon의 named pipe 패턴이 있는가?"같은 질문을 분 단위로 답할 수 있습니다.

위협 사냥(Threat Hunting)은 알람을 기다리지 않고 가설을 세워 능동적으로 IoC와 TTP를 추적하는 활동입니다. 표준 프레임워크는 ① Sqrrl 사이클(가설 → 도구·기법 → 발견 → 분석 → 정보화), ② MITRE ATT&CK 기반 가설(예: "T1003.001 LSASS dump가 도메인 내에서 발생하고 있는가?"), ③ Pyramid of Pain(David Bianco)에 따라 hash/IP보다는 TTP 단위 탐지를 지향합니다.

수학적·정량적 기초

$$\text{MTTD} + \text{MTTR} = \text{dwell time}, \quad \text{모든 IR KPI의 핵심}$$ $$\text{사고 손실: } L = \sum (\text{기간} \times \text{시간당 매출}) + \text{복구비용} + \text{규제 벌금} + \text{평판 손실}$$ $$\text{탐지 우선순위 (FAIR): } \text{Risk} = \text{LEF} \times \text{Loss Magnitude}$$

Mandiant M-Trends 2024에 따르면 글로벌 평균 dwell time이 10일까지 단축됐지만, 랜섬웨어 그룹의 평균 침입-암호화 간격은 24시간 미만으로 떨어졌습니다. 즉 방어자의 탐지가 빨라진 만큼 공격자도 빨라진 것이고, "탐지→격리까지 60분" 같은 작은 차이가 실질 피해를 결정합니다. SOC SLA의 P1 응답 시간을 15분 → 5분으로 단축하는 운영 투자가 ROI 측면에서 최고 수익을 냅니다.

최신 연구와 frontier

① LLM-assisted IR: Microsoft Security Copilot, Google Sec-Gemini, CrowdStrike Charlotte AI가 알람 트리아지·로그 요약·플레이북 추천을 자동화. 2024년 베타·GA가 본격화. ② eBPF 포렌식: Tetragon/Aqua/Falco로 컨테이너의 휘발성·짧은 수명 워크로드에서도 syscall 단위 증거 수집. ③ Sigma Correlation v2(2024)로 다단계 공격 탐지가 표준화됨. ④ cloud-native EDR: SaaS·IaaS의 audit log(CloudTrail, Azure Activity, Workspace Admin)와 endpoint를 연결하는 unified investigation graph. ⑤ OWASP IR Top 10(드래프트)은 IR 자체의 실패 패턴을 정리 중.
